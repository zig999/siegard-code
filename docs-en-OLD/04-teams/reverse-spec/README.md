# Reverse Spec Team

Generates technical specifications from existing source code through automated analysis.

## When to use

- Projects without documentation
- Legacy code that needs formal specifications
- Onboarding to understand an existing codebase
- Creating a baseline before major refactoring

## Agents

| Agent | Role | Input | Output |
|-------|------|-------|--------|
| **[Orchestrator](orchestrator.md)** | Pipeline coordination | Code directory | `log-reverse-spec.md` |
| **[Analyzer](analyzer.md)** | Source code scanning | Source code | `_temp/analysis-report.md` |
| **[Writer](writer.md)** | Spec generation | Analysis report | Draft specs in `{SPECS_DIR}` |

## Pipeline

```
Orchestrator -> Analyzer -> Writer
```

## Operating modes

| Mode | Trigger | Behavior |
|------|---------|----------|
| **Detection** | No `{SPECS_DIR}` exists | Generate all specs from scratch |
| **Merge** | `{SPECS_DIR}` already exists | Compare with existing, flag divergences |

## Stack auto-detection

The Analyzer automatically identifies the project's technology stack by examining:
- Dependency manifests (package.json, requirements.txt, pom.xml, etc.)
- File patterns and directory structure
- Import statements and framework-specific patterns

This makes the reverse spec process stack-agnostic -- it adapts to whatever technology it finds.

## Important limitation

All artifacts generated by `/u-reverse-spec` receive `draft` status. They must be formally reviewed and approved through `/u-spec` before being used for development.
